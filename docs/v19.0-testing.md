# Fileserver v19 release-QA contract

## Scope

The release gate is deliberately limited to the product's supported main
flow. It proves a configured Debian Trixie root, completed firstboot, Samba and
explicit-TLS FTP authentication, an upload/download/delete round trip across
service restart, the landing CGI Host boundary, and signed package/update
provenance. Installer, hardware, performance and UI polish are outside this
Docker gate.

used in generated links; all other input falls back to `localhost` rather than
entering HTML attributes.

## Evidence crosswalk

| Boundary | Required evidence |
| --- | --- |
| Build and init | Configured Trixie root, import, completed firstboot and active multi-user/Samba/Pure-FTPd/Apache/Postfix services. |
| Credentials | Root password rotated from the build state, supplied password absent from firstboot/auth logs, invalid SMB/FTPS credentials rejected. |
| File service | Authenticated SMB and explicit-TLS FTP upload/download/delete, exact content comparison and successful read after service restart. |
| Landing CGI | A normal Host produces the intended local management links; hostile attribute/script input is rejected and never reflected. |
| Persistence | Uploaded content remains readable after Samba and Pure-FTPd service restarts. |
| Packages and updates | Exact installed Samba/Pure-FTPd/Apache versions, signed `apt-get update`, eligible Trixie index targets/candidates, unchanged installed versions and no Bookworm source. |

The final disposition must bind the exact tested commit, evidence manifest and
shared TurnKey common source identity used by TKLDev. Appliance QA may report
`PASS`; `SHIP_RELEASE` additionally requires a separate execution/diff review,
clean local master/archive integration and removal of the candidate worktree.
